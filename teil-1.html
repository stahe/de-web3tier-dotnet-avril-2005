    1.2. Die Webanwendung „webarticles“

    Wir stellen hier die Elemente einer vereinfachten E-Commerce-Webanwendung vor. Diese ermöglicht es Webkunden:

    • eine Liste von Artikeln aus einer Datenbank einzusehen
    • bestimmte Artikel in einen elektronischen Warenkorb zu legen
    • diesen zu bestätigen. Diese Bestätigung hat lediglich zur Folge, dass die Bestände der gekauften Artikel in der Datenbank aktualisiert werden.

    Dem Benutzer werden folgende Ansichten angezeigt:

    - die Ansicht „LISTE“, die eine Liste der zum Verkauf stehenden Artikel anzeigt
    - die Ansicht „[INFOS]“, die zusätzliche Informationen zu einem Produkt liefert:
    • die Ansichten „[PANIER]“ und „[PANIERVIDE]“, die den Inhalt des Warenkorbs des Kunden anzeigen
    • die Ansicht [ERREURS], die etwaige Fehler der Anwendung meldet

    1.3. Allgemeine Architektur der Anwendung

    Wir möchten eine Anwendung mit der folgenden dreischichtigen Struktur erstellen:

    • Die drei Schichten werden durch die Verwendung von Schnittstellen voneinander unabhängig gemacht
    • Die Integration der verschiedenen Schichten erfolgt über Spring
    • Jede Schicht verfügt über separate Namespaces: Web (Schicht UI), Domain (Geschäftslogik-Schicht) und DAO (Datenzugriffsschicht).

    Die Anwendung folgt einer MVC-Architektur (Model-View-Controller). Wenn wir das obige Schichtschema heranziehen, fügt sich die Architektur wie folgt ein:

    Die Bearbeitung einer Anfrage eines Kunden erfolgt in folgenden Schritten:

    1. Der Kunde sendet eine Anfrage an den Controller. Dieser Controller ist hier eine .aspx-Seite, der eine besondere Rolle zukommt. Sie empfängt alle Anfragen der Kunden. Sie ist das Eingangstor der Anwendung. Sie entspricht dem C in MVC.
    1. Der Controller verarbeitet diese Anfrage. Dazu benötigt er möglicherweise die Unterstützung der Geschäftslogikschicht, die in der Struktur MVC als Modell M bezeichnet wird.
    2. Der Controller erhält eine Antwort von der Geschäftslogikschicht. Die Anfrage des Kunden wurde bearbeitet. Dies kann zu mehreren möglichen Antworten führen. Ein klassisches Beispiel ist
      • eine Fehlerseite, falls die Anfrage nicht korrekt verarbeitet werden konnte
      • ansonsten eine Bestätigungsseite
    3. Der Controller wählt die Antwort (= Ansicht) aus, die an den Client gesendet werden soll. Dabei handelt es sich meist um eine Seite mit dynamischen Elementen. Der Controller stellt diese der Ansicht zur Verfügung.
    4. Die Ansicht wird an den Client gesendet. Dies ist das „V“ in MVC.

    1.4.3.3. Die Implementierungsklasse [ArticlesDaoArrayList]

    Die Implementierungsklasse [ArticlesDaoArrayList] ist wie folgt definiert:

    Imports System
Imports System.Collections

Namespace istia.st.articles.dao

    Public Class ArticlesDaoArrayList
        Implements istia.st.articles.dao.IArticlesDao

        Private articles As New ArrayList
        Private Const nbArticles As Integer = 4

         ' Standardhersteller
        Public Sub New()
             ' Es werden einige Artikel erstellt
            For i As Integer = 1 To nbArticles
                articles.Add(New Article(i, "article" + i.ToString, i * 10, i * 10, i * 10))
            Next
        End Sub

         ' Liste aller Artikel
        Public Function getAllArticles() As IList Implements IArticlesDao.getAllArticles
             ' Die Liste der Artikel wird zurückgegeben
            SyncLock Me
                Return articles
            End SyncLock
        End Function

         ' Alle Artikel löschen
        Public Sub clearAllArticles() Implements IArticlesDao.clearAllArticles
             ' Die Artikelliste wird geleert
            SyncLock Me
                articles.Clear()
            End SyncLock
        End Sub

         ' einen Artikel anhand seines Schlüssels abrufen
        Public Function getArticleById(ByVal idArticle As Integer) As Article Implements IArticlesDao.getArticleById
             ' Artikel in der Liste suchen
            SyncLock Me
                Dim ipos As Integer = posArticle(articles, idArticle)
                If ipos <> -1 Then
                    Return CType(articles(ipos), Article)
                Else
                    Return Nothing
                End If
            End SyncLock
        End Function

         ' einen Artikel zur Artikelliste hinzufügen
        Public Function ajouteArticle(ByVal unArticle As Article) As Integer Implements IArticlesDao.ajouteArticle
             ' Der Artikel wird zur Artikelliste hinzugefügt
            SyncLock Me
                 ' Es wird überprüft, ob er nicht bereits vorhanden ist
                Dim ipos As Integer = posArticle(articles, unArticle.id)
                If ipos <> -1 Then
                    Throw New Exception("L'article d'id [" + unArticle.id.ToString + "] existe déjà")
                End If
                 ' Der Artikel wird hinzugefügt
                articles.Add(unArticle)
                 ' das Ergebnis wird zurückgegeben
                Return 1
            End SyncLock
        End Function

         ' einen Artikel bearbeiten
        Public Function modifieArticle(ByVal articleNouveau As Article) As Integer Implements IArticlesDao.modifieArticle
             ' einen Artikel bearbeiten
            SyncLock Me
                 ' Es wird geprüft, ob er existiert
                Dim ipos As Integer = posArticle(articles, articleNouveau.id)
                 ' falls er nicht existiert
                If ipos = -1 Then Return 0
                 ' er existiert – man bearbeitet ihn
                articles(ipos) = articleNouveau
                 ' das Ergebnis wird zurückgegeben
                Return 1
            End SyncLock
        End Function

         ' einen durch seinen Schlüssel identifizierten Artikel löschen
        Public Function supprimeArticle(ByVal idArticle As Integer) As Integer Implements IArticlesDao.supprimeArticle
             ' Löschen eines Artikels
            SyncLock Me
                 ' Es wird geprüft, ob er vorhanden ist
                Dim ipos As Integer = posArticle(articles, idArticle)
                 ' Falls er nicht existiert
                If ipos = -1 Then Return 0
                 ' er existiert – er wird gelöscht
                articles.RemoveAt(ipos)
                 ' das Ergebnis wird zurückgegeben
                Return 1
            End SyncLock
        End Function

         ' den Bestand eines Artikels ändern, der durch seinen Schlüssel identifiziert wird
        Public Function changerStockArticle(ByVal idArticle As Integer, ByVal mouvement As Integer) As Integer Implements IArticlesDao.changerStockArticle
             ' Bestand eines Artikels ändern
            SyncLock Me
                 ' Es wird geprüft, ob er vorhanden ist
                Dim ipos As Integer = posArticle(articles, idArticle)
                 ' falls er nicht vorhanden ist
                If ipos = -1 Then Return 0
                 ' Er existiert – sein Bestand wird geändert, sofern dies möglich ist
                Dim unArticle As Article = CType(articles(ipos), Article)
                 ' Der Bestand wird nur geändert, wenn er ausreichend ist
                If unArticle.stockactuel + mouvement >= 0 Then
                    unArticle.stockactuel += mouvement
                    Return 1
                Else
                    Return 0
                End If
            End SyncLock
        End Function

         ' einen Artikel anhand seines Schlüssels suchen
        Private Function posArticle(ByVal listArticles As ArrayList, ByVal idArticle As Integer) As Integer
             ' gibt die Position des Artikels [idArticle] in der Liste zurück oder -1, falls er nicht gefunden wurde
            Dim unArticle As Article
            For i As Integer = 0 To listArticles.Count - 1
                unArticle = CType(listArticles(i), Article)
                If unArticle.id = idArticle Then
                    Return i
                End If
            Next
             ' nicht gefunden
            Return -1
        End Function
    End Class

End Namespace

    Anmerkungen:

    • Die Datenquelle wird durch das private Feld [articles] vom Typ [ArrayList] simuliert
    • Der Konstruktor der Klasse legt standardmäßig 4 Einträge in der Datenquelle an.
    • Alle Methoden für den Datenzugriff wurden synchronisiert, um Probleme durch gleichzeitigen Zugriff auf die Datenquelle zu vermeiden. Zu einem bestimmten Zeitpunkt hat jeweils nur ein Thread Zugriff auf eine bestimmte Methode.
    • Die Methode [posArticle] ermöglicht es, die Position [0..N] eines Artikels, der durch seine Nummer identifiziert wird, in der Quelle [ArrayList] zu ermitteln. Existiert der Artikel nicht, gibt die Methode die Position -1 zurück. Diese Methode wird wiederholt von den anderen Methoden aufgerufen.
    • Die Methode [ajouteArticle] ermöglicht es, einen Artikel zur Artikelliste hinzuzufügen. Sie gibt die Anzahl der eingefügten Artikel zurück: 1. Wenn der Artikel bereits existierte, wird eine Ausnahme ausgelöst.
    • Die Methode [modifieArticle] ermöglicht es, einen vorhandenen Artikel zu ändern. Sie gibt die Anzahl der geänderten Artikel zurück: 1, wenn der Artikel vorhanden war, andernfalls 0.

    1.5.4. Die <asp:>-Tag-Bibliothek

    Betrachten wir die Ansicht [ERREURS], die eine Fehlerliste anzeigt:

    Die Ansicht [ERREURS] ist dafür zuständig, eine Fehlerliste anzuzeigen, die das Controller-Element [main.aspx] unter dem Namen [context.Items("erreurs")] in den Anforderungskontext gestellt hat.     Zur Erinnerung: Eine Seite ASPX besteht aus einem Layout-Teil HTML und einem Code-Teil .NET, der die Daten aufbereitet, die der Layout-Teil anzeigen soll. Diese beiden Teile können sich in derselben Datei [aspx] (Lösung WebMatrix) oder in zwei Dateien befinden: [aspx] für die Darstellung, [aspx.vb] für den Code. Letztere Lösung wird von Visual Studio verwendet. Um die Sache noch komplizierter zu machen, kann der Layout-Teil HTML ebenfalls Code enthalten (NET), was die Trennung zwischen [contrôleur] und [présentation] aus der Ansicht heraus verwischt. Von dieser Vorgehensweise wird im Allgemeinen dringend abgeraten. Um den gesamten Code aus dem [présentation]-Teil zu entfernen, mussten Tag-Bibliotheken erstellt werden. Diese „verbergen“ den Code unter dem Deckmantel von Tags, die den HTML-Tags ähneln. Wir stellen zwei mögliche Lösungen für die Seite [ERREURS] vor.

    Unsere erste Lösung verwendet Code aus .NET im Teil [présentation] der Seite. Die Seite ASPX ruft die in der Anfrage enthaltene Fehlerliste in ihrem Controller-Teil [erreurs.aspx.vb] ab:

...
             ' Fehler werden abgerufen

        End Sub

    und zeigt es dann im Bereich [présentation, erreurs.aspx] an:

                    <h2>Les erreurs suivantes se sont produites :</h2>
                <ul>
                <%
                    for i as integer=0 to erreurs.count-1
                        response.write("<li>" & erreurs(i).ToString & "</li>")
                    next
                %>
                </ul>

    Die zweite Lösung nutzt das Tag <asp:repeater> aus der Tag-Bibliothek <asp:> von ASP.NET. Wenn man eine Seite ASPX grafisch erstellt, steht dieses Tag als Serverkomponente zur Verfügung, die man auf das Entwurfsformular zieht. Wenn man den Code ASPX manuell erstellt, spricht man von einer Tag-Bibliothek.

    Mit der Tag-Bibliothek <asp:> sieht der Code ASPX der vorherigen Ansicht [ERREURS] wie folgt aus:

            <asp:Repeater id="rptErreurs" runat="server">
            <HeaderTemplate>
                <h3>Les erreurs suivantes se sont produites :
                </h3>
                <ul>
            </HeaderTemplate>
            <ItemTemplate>
                <li>
                    <%# Container.DataItem %>
                </li>
            </ItemTemplate>
            <FooterTemplate>
                </ul>
            </FooterTemplate>
        </asp:Repeater>

    Das Tag

            <asp:Repeater id="rptErreurs" runat="server">

    dient dazu, ein Muster HTML auf die verschiedenen Elemente einer Datenquelle anzuwenden. Die verschiedenen Elemente lauten wie folgt:

    HeaderTemplate
    das Muster HTML, das angezeigt werden soll, bevor die Elemente der Datenquelle angezeigt werden
    ItemTemplate
    das Muster HTML, das für jedes Element der Datenquelle wiederholt werden soll. Der Ausdruck [<%# Container.DataItem %>] dient dazu, den Wert des aktuellen Elements der Datenquelle anzuzeigen
    FooterTemplate
    Das Muster HTML wird angezeigt, nachdem die Elemente der Datenquelle angezeigt wurden

    Die Datenquelle wird in der Regel im Abschnitt [contrôleur] der Seite mit dem Tag verknüpft:

    1.5.7. Die Controller global.asax, main.aspx

    Nun muss noch das Herzstück unserer Webanwendung geschrieben werden: der Controller. Seine Aufgabe besteht darin:

    • die Anfrage des Clients entgegenzunehmen,
    • die vom Kunden angeforderte Aktion mithilfe der Geschäftsklassen zu verarbeiten,
    • als Antwort die entsprechende Ansicht zurückzusenden.

    1.5.7.1. Der Controller [global.asax.vb]

    Wenn die Anwendung ihre allererste Anfrage erhält, wird die Prozedur [Application_Start] aus der Datei [global.asax.vb] ausgeführt. Dies geschieht nur ein einziges Mal. Die Prozedur [Application_Start] dient dazu, die für die Webanwendung erforderlichen Objekte zu initialisieren, die von allen Client-Threads schreibgeschützt gemeinsam genutzt werden. Diese gemeinsam genutzten Objekte können an zwei Stellen abgelegt werden:

    • in den privaten Feldern des Controllers
    • im Ausführungskontext der Anwendung (Application)

    Die Methode [Application_Start] der Anwendung [global.asax.vb] führt folgende Aktionen durch:

    • Sie prüft, ob in der Datei [web.config] die für den ordnungsgemäßen Betrieb der Anwendung erforderlichen Parameter vorhanden sind. Diese wurden in Abschnitt 1.5.3 beschrieben.
    • überträgt die Liste eventueller Fehler in Form eines Objekts vom Typ [ArrayList erreurs] in den Anwendungskontext. Diese Liste ist leer, wenn keine Fehler vorliegen, existiert aber dennoch.
    • Wenn Fehler aufgetreten sind, endet die Methode [Application_Start] an dieser Stelle. Andernfalls fordert sie die Referenz eines Singletons vom Typ [IArticlesDomain] an, bei dem es sich um das Geschäftsobjekt handelt, das der Controller für seine Zwecke verwenden wird. Wie in 1.5.3.2 erläutert, fordert der Controller dieses Singleton vom Spring-Framework an. Bei dieser Instanziierung können verschiedene Fehler auftreten. Ist dies der Fall, werden diese wiederum im Objekt [erreurs] des Anwendungskontexts gespeichert.

    Der Controller [global.asax.vb] verfügt über eine Prozedur [Session_Start], die bei jedem neuen Kunden aufgerufen wird. In dieser Prozedur wird ein leerer Warenkorb für den Kunden angelegt. Dieser Warenkorb wird über alle Anfragen dieses bestimmten Kunden hinweg beibehalten. Der Code könnte wie folgt aussehen:

            Dim strId As String = Request.QueryString("id")
             ' Gibt es etwas?
            If strId Is Nothing Then

            Catch ex As Exception

            context.Items("msg") = ""
            context.Items("qte") = ""
